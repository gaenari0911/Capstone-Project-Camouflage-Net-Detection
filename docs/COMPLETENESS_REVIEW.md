# 졸업작품 완성도 검토 · 2026-09-27

## 결론

**소프트웨어4학년 졸업작품으로 제출 가능한, 실험·구현·분석이 갖춰진 연구 프로토타입이다.** 이는 저장된 산출물을 근거로 한 정성 평가이며 학교 루브릭·지도교수의 평가나 특정 학점을 보장하지 않는다. 추가 실험보다 명확한 발표·안정적인 시연·공개 코드 정리가 현재 우선순위다.

| 항목 | 관찰 근거 | 평가 |
| --- | --- | --- |
| 문제 정의 | 실제 데이터 부족을 합성으로 보완하는 명확한 질문 | 충분 |
| 구현 | 합성/선택/학습/평가 자동화, custom model, 장애 재개·자원 관리 | 충분 |
| 실험 | 현재40개 학습,34개Test, A/H, Main/Low/BG,1학기 맥락 | 졸업작품 범위에서 충분 |
| 결과 분석 | 긍정·부정 결과, seed변동, 오탐/미탐 trade-off,한계 공개 | 충분 |
| 발표·시연 | 저장된14사례/200장/10모델 비교, 실제 업로드 추론 검증 기록 | 준비됨; 발표 현장 점검은 별도 |
| 연구 타당성 | 고정 split,Val-best,출처/hash 검사 | 제한을 명시한 수준에서 타당 |
| 외부 재현성 | 서버내 완료/회귀 근거 있음; 데이터·checkpoint 미공개 | 부분 재현 가능; clean GPU clone 재현 미검증 |
| 제품 수준 | 실제 운용 데이터·현장 성능/보안/SLA 검증 없음 | 연구 프로토타입, 제품 보증 아님 |

## 강점과 개선 우선순위

단순 모델1회 학습이 아니라 데이터 전략, 구조,실제 부족,배경 추가까지 연결된 비교 실험이다. 결과가 가설과 다를 때도 숨기지 않았고, 실행 재개와 데이터 출처 검증 같은 소프트웨어 공학적 작업이 있다.

남은 우선순위는 발표에서 연구 질문과 핵심 수치를 간결하게 연결하고, “왜task-aware가 항상 좋지 않았는가?”, “왜1학기와 단순비교하면 안 되는가?”, “왜배경은 오탐과미탐을 동시에 바꾸는가?”를 설명하는 것이다. 원인을 검증하지 않은 부분은 가능성으로만 말한다. 데모는 오프라인 대체안을 준비하고 좋은 사례와 실패 사례를 함께 보여준다.

## 이번 GitHub 준비에서 확인한 개선점

기존 README가2줄이고 정식 실험 코드가 아직 원격main에 없는 상태였다. Dataset.zip과AnyDoor가상환경도 기존 ignore에서 누락돼 있었다. 공개 준비 브랜치에서는 코드/집계 결과를 허용 목록으로 옮기고 대용량·개인 설정을 제외하며 모델 의존성과 공개 범위를 명시했다.

서버에서 GPU를 실행하지 않는 핵심 테스트21개를 다시 통과했다(스케줄러·휴리스틱18, AnyDoor선택3). 새 공개 사본의 검증 결과는 PR/CI와 `tools/verify_public_results.py`를 기준으로 별도 확인한다. 기존 완료 감사와 현재 clean-clone 검증을 혼동하지 않는다.
