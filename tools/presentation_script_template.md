## 1. 연구 질문

“위장 객체는 배경과 구분하기 어렵고, 실제 라벨 데이터를 충분히 확보하기도 어렵습니다. 저희는 합성데이터를 만드는 시스템을 구현하고, 어떤 생성·선택 방식이 실제 분할 성능을 개선하는지 검증했습니다.”

## 2. 1학기의 출발점

“1학기에는 custom DualHeadSegment와 휴리스틱 합성을 구현했습니다. 실제 데이터와 background를 사용한 조건에서 합성을 추가하면 Test mask mAP50–95가 27.76에서 34.86으로 증가했습니다. 이 값은 당시 보관 결과이고, 이번 학기의 3개 seed 평균과 동일 조건 비교는 아닙니다.”

Hard Mining 후 mAP가 더 좋아지지 않았다는 결과도 함께 보여준다. 모든 후속 기법이 성공했다는 흐름으로 설명하지 않는다.

## 3. 왜 후속 연구가 필요한가

“합성이 도움이 된다는 관찰에서 더 나아가, 실제 데이터가 부족해도 효과가 있는지, 생성 방식이나 선택 기준을 바꾸면 어떻게 되는지, 모델의 추가 구성이 필요한지 나누어 확인했습니다.”

## 4. 시스템 구현

“데이터 출처를 기록하고 합성 후보를 생성한 뒤, 선택·학습·모델 동결·평가·보고서 생성을 연결했습니다. 장시간 실행 중 중단되더라도 체크포인트에서 재개하고, 파일 해시로 입력과 결과를 추적할 수 있도록 구현했습니다.”

이전 학기의 학습 완료 best를 그대로 계승한 것이 아니라, 공통 pretrained와 seed별 초기화 기준에서 독립 학습했다는 점을 설명한다.

## 5. 실험 설계

“실제 Train/Validation/Test는 748/100/200장입니다. Low-data는 고정된 실제 187장이고, 합성 객체 출처와 Judge도 그 범위로 제한했습니다. 주요 M/L/BG 실험은 3개 seed, A/H는 seed0입니다. 정식 합성 33,000장과 이번 학기 학습 40개를 수행했으며 A6개는 Validation screening으로 구분했습니다.”

## 6. 주요 성능

“전체 실제 데이터를 사용하면 실제-only의 21.03에서 AnyDoor random의 31.99로, 25% 실제 데이터를 사용하면 12.85에서 22.01로 증가했습니다. 표의 ±는 학습 seed의 표본 표준편차입니다. 합성의 보완 가능성은 확인했지만 추가 학습량과 외부 자원을 사용했기 때문에 실제 데이터를 75% 대체했다고 단정하지는 않습니다.”

## 7. 학습이 정상적으로 수행됐는가

“40개 모두 예정된 epoch를 완료했습니다. Validation-best 체크포인트와 Test 평가의 연결을 검증했습니다. 학습 loss가 감소했다는 사실과 최종 일반화 성능은 구분해 판단했습니다.”

## 8. 합성 효과를 눈으로 보기

demo.html에서 사례01과03을 연달아 보여준다.

“같은 이미지에서 M0는 객체를 놓쳤고 M2는 union IoU 0.916으로 분할했습니다. 반대로 다른 이미지에서는 0.584에서 0으로 악화했습니다. 이들은 차이를 설명하기 위해 사후 선별한 사례이며, 평균 성능을 대표하는 표본은 아닙니다. 전체 200장의 예측도 이 화면에서 확인할 수 있습니다.”

화면의 union IoU가 공식 mAP와 다르다는 점을 덧붙인다. 확대 화면 뒤에는 전체 화면으로 돌아와 배경 오탐도 보여준다.

## 9. Heuristic ablation

“Tone score를 제외한 A2는 Validation 23.36으로 가장 높았고 Full A1은 21.73이었습니다. 따라서 모든 선택 score가 필요하다는 가설은 지지되지 않았습니다. 이는 렌더링 자체를 제거한 실험이 아니며, seed0·40 epochs의 탐색 결과입니다.”

## 10. Head ablation

“합성 조건의 H0/H1/H2는 각각 29.16/30.71/29.90이었습니다. Boundary 보조 학습에는 관찰상 이점이 있지만, 거리 가중치의 추가 우위는 일관되지 않았습니다. 단일 seed 결과이므로 일반적인 구조 우위를 주장하지 않습니다.”

## 11. Task-aware의 부정 결과

“Random 대비 task-aware는 M에서 −2.01pp, L에서 −1.76pp였습니다. 난도가 높다고 모두 유익한 학습 자료는 아니었습니다. 분포 변화나 label noise는 가능한 설명이지만, 원인을 입증한 추가 실험은 수행하지 않았습니다.”

## 12. Background 2×2

“합성 유무와 background 유무를 교차했습니다. M0/M1에 동일한 배경 2,129장을 추가했더니 오탐은 각각 61.9%/51.9% 감소했지만 mAP는 3.31/2.30pp 낮아졌습니다. Background 추가 자체가 전체 성능 개선으로 이어지지는 않았습니다.”

## 13. 오탐–미탐 절충 시연

demo05에서 오탐 감소를, demo06에서 미탐 증가를 보여준다.

“여기서는 예측이 줄어 오탐이 감소하지만, 정답 객체까지 놓칠 수 있습니다. Precision 상승만으로 성공이라고 판단하면 안 됩니다. 운영 목적에 따라 오탐과 미탐 중 무엇이 더 중요한지도 달라집니다.”

사례05는 오탐3개가0개로 줄었지만 정답 객체는 두 모델 모두 놓친 예시다. 정답 검출을 유지하면서 오탐만 줄인 성공 사례라고 소개하면 안 된다.

## 14. 실제 소프트웨어 시연

로컬 서버를 실행한 경우 새 이미지를 업로드하고 결과를 저장한다.

“이 기능은 선택한 동결 모델로 새 이미지를 실제 추론합니다. 화면의 추론 시간과 첫 모델 로딩 시간을 구분했고, 정답이 없는 이미지에 정확도나 IoU를 표시하지 않았습니다.”

오프라인 사례 재생만 사용하는 상황이라면 저장된 실제 예측을 재생하는 데모라고 정확히 소개한다.

## 15. 해석의 한계

“같은 epoch라도 데이터가 늘면 업데이트 횟수가 증가하므로 동일 compute 비교는 아닙니다. 작은 고정 Test, A/H의 단일 seed, 합성 근사 마스크, 학기간 recipe 차이와 background 사후 평가도 한계입니다. 동일 update 통제와 독립 외부 데이터 검증은 후속 연구로 남겼습니다.”

## 16. 최종 기여

“합성은 실제 데이터 부족을 보완했지만, 복잡한 선택·구조가 항상 유리하지는 않았습니다. Background의 오탐–미탐 절충까지 확인했습니다. 이 결과를 재현할 수 있는 생성·학습·복구·평가 시스템과 근거를 남긴 것이 작품의 기여입니다.”

## 예상 질문과 답변

**1학기보다 수치가 낮은데 실패인가?** 보관된 S3의34.86은 이번 M2 평균31.99보다 높다. 다만 recipe·background·평가 경로 등이 달라 통제된 방법 비교가 아니다. 각 학기 내부의 합성 효과는 확인했고, 이번에는 조건별 검증과 재현성을 확장했다.

**왜 task-aware가 더 낮았나?** 현재 기준의 우위가 확인되지 않았다. 난도 점수가 유용한 정보와 생성 오류를 구분하지 못하거나 분포를 바꿨을 가능성은 있지만, 원인을 입증한 추가 실험은 없다.

**그림을 좋은 것만 골랐나?** 큰 차이를 보여주는 설명용 선정임을 공개했고, 악화·미탐·중간·고정 난수 사례와 전체200장 예측도 제공했다. 평균 성능 주장은 선별 사례가 아닌 전체 Test와3seed 표에서 한다.

**같은 epoch인데 공정한가?** 설정은 같지만 업데이트 수가 달라 동일 compute 비교는 아니다. 현재 결과는 실용적인 증강 recipe 비교이고 순수 데이터 효과만 분리한 주장은 하지 않는다.

**화면 IoU와 mAP는 왜 다른가?** 화면은 한 이미지의 합집합 mask IoU다. 공식 mAP는 instance matching, confidence 순위, IoU .50~.95를 사용한다. 서로 대체할 수 없는 지표다.

**본인이 설명할 수 있어야 하는 구현 지점은?** 출처 제한과 split, 학습 전용 boundary head, 공통 초기화, checkpoint 복구, Validation 선택과 Test 평가의 분리, 동일 후보의 random/task-aware 선택, background 빈 라벨 처리다. 실제 코드를 가리키며 설명할 수 있도록 준비한다.
