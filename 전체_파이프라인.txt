--------------------------------------------------
[중요 변경: OBJECT QUOTA 기반 구조]
--------------------------------------------------

기존 문제:
- 점수 높은 객체가 반복 선택됨
- 특정 객체 과다 사용
- 데이터 다양성 붕괴

해결 전략:
👉 "선택"이 아니라 "배정"을 먼저 수행

--------------------------------------------------
[9-1] 객체 quota 사전 생성
--------------------------------------------------

각 domain별로 수행:

object_list shuffle

1차:
모든 객체에 1회씩 부여

2차:
남은 샘플 수를 round-robin 분배

제약:
- 기본 max: 5회
- 부족 시에만 6~7 허용

결과:

usage_state = {
  domain: {
    "remaining_quota": {obj_id: count},
    "used_total": {obj_id: 0},
    "used_by_domain": {obj_id: {}},
    "used_by_background": {obj_id: {}}
  }
}

--------------------------------------------------
[9-2] 후보 생성 (Search 단계)
--------------------------------------------------

기존:
→ 점수 기반 랜덤 선택

변경:
→ quota 기반 필터링

조건:

candidate if:

- remaining_quota > 0
- recent_history에 없음
- 현재 background 과다 사용 아님

즉:
👉 usage_count 대신 remaining_quota 기준

--------------------------------------------------
[9-3] 평가 (Selection 단계)
--------------------------------------------------

기존 유지 + penalty 추가

(1) 객체-배경 적합도
- brightness diff
- contrast diff
- saturation diff

(2) 위치 적합도
- sky penalty
- low texture penalty
- 위치 penalty

--------------------------------------------------
[추가 penalty]
--------------------------------------------------

- 같은 object + 같은 domain 반복 → 감점
- 같은 object + 같은 background → 강한 감점
- recent N개 등장 object → 제외 또는 큰 감점

--------------------------------------------------
[최종 priority]
--------------------------------------------------

priority =
  remaining_quota 높은 객체
+ recent_history 없는 객체
+ domain에서 덜 쓰인 객체
+ background에서 덜 쓰인 객체
+ score

--------------------------------------------------
[9-4] 선택 후 업데이트
--------------------------------------------------

선택된 객체에 대해:

remaining_quota -= 1
used_total += 1
used_by_domain[domain] += 1
used_by_background[bg] += 1
